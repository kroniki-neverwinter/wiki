# Kroniki Neverwinter Wiki

Frontend application and content repository for the **Kroniki Neverwinter** community wiki. This is a hobby project maintained in contributors' spare time, built as a practical frontend and documentation space for the community.

The site is a static documentation portal built with Docusaurus, with custom React pages for the homepage and character-card flow.

> **Hobby project:** Features, content updates and maintenance are handled on a best-effort basis.

**Live site:** [wiki.nwn.net.pl](https://wiki.nwn.net.pl)

## Tech stack

- [Docusaurus 3](https://docusaurus.io/) - static-site generator and documentation framework
- React 18
- MDX / Markdown - wiki content
- CSS Modules and custom global CSS
- Algolia DocSearch - site search
- Azure Pipelines - CI/CD

## Prerequisites

- Node.js 18+ (Node.js 20 is used in CI)
- npm

## Getting started

```bash
git clone <repository-url>
cd wiki
npm ci
npm start
```

The development server runs at `http://localhost:3000` by default and reloads after file changes.

> On Windows PowerShell environments that block `npm.ps1`, use `npm.cmd` instead, for example: `npm.cmd start`.

## Scripts

| Command | Description |
| --- | --- |
| `npm start` | Starts the local development server. |
| `npm run build` | Creates an optimized production build in `build/`. |
| `npm run serve` | Serves the production build locally. |
| `npm run clear` | Clears Docusaurus-generated caches. |
| `npm run deploy` | Runs Docusaurus deployment; requires deployment credentials. |
| `npm run write-translations` | Generates translation files. |
| `npm run write-heading-ids` | Adds explicit heading IDs to documentation files. |

Run a production build before opening a pull request:

```bash
npm run build
```

The Docusaurus configuration treats broken links as build errors.

## Project structure

```text
docs/                       Main wiki documentation
wiedza-o-swiecie/           "World knowledge" documentation plugin
informacje-o-swiecie/       Additional world-information content
src/
  components/               Shared React components and API URL constants
  css/custom.css            Global theme overrides
  pages/                    Custom routes, homepage and character-card page
static/                     Public assets copied unchanged to the site root
docusaurus.config.js        Site, navigation, docs and Algolia configuration
sidebars.js                 Autogenerated main documentation sidebar
sidebarsInfo.js             Manually curated world-knowledge sidebar
azure-pipelines.yml         CI/CD pipeline
```

## Content development

### Main wiki

Add Markdown or MDX files under `docs/`. The main sidebar is autogenerated from the directory structure, so new pages appear automatically.

### World knowledge

Content under `wiedza-o-swiecie/` is served by a separate Docusaurus docs plugin at `/wiedza-o-swiecie`. Add visible pages to `sidebarsInfo.js` as well as creating the content file.

### Static assets

Place images and downloadable files in `static/`. They are served from the site root:

```md
![Example image](/img/wiki/example.png)
```

### Page metadata

Use front matter to control document metadata and routes when needed:

```md
---
id: example-page
title: Example page
slug: /example
---
```

Avoid changing existing filenames or paths without checking inbound links; document paths form part of the published URLs.

## Environment variables

Algolia search is configured through environment variables:

```env
ALGOLIA_APP_ID=
ALGOLIA_API_KEY=
ALGOLIA_INDEX_NAME=
```

Store local values in `.env.local` (or `.env` for local-only work). Do not commit credentials. A missing Algolia configuration affects search, but does not prevent general UI development.

## Integrations

The character-card page includes a Discord OAuth flow and submits data to an external API. The endpoint constants are kept in `src/components/const/urls.js`.

When changing this flow, verify both unauthenticated and authenticated states, and avoid exposing new credentials in client code.

## Deployment

Azure Pipelines runs for commits pushed to `main`. The pipeline uses Node.js 20, installs dependencies, runs the Docusaurus deployment command, and receives deployment and Algolia credentials as secure pipeline variables.

Never add secrets, personal access tokens, OAuth client secrets, or webhook URLs to source-controlled files.

## Developer checklist

- Run `npm run build` successfully.
- Check navigation and internal links for updated documentation.
- Verify responsive rendering for custom React pages.
- Keep static-asset paths rooted at `/`.
- Do not commit `.env*` files or credentials.
